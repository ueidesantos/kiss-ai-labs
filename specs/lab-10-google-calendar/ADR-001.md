# ADR-001: Use a recruiter-supplied Google Calendar booking link

- **Status:** Accepted
- **Date:** 2026-10-20
- **Owners:** User / Coordinator
- **Related requirements:** REQ-1–REQ-7, NFR-2–NFR-5

## Context

The recruiter wants to introduce a candidate to a role and let the candidate book an interview from the recruiter's availability. The recruiter has not approved a production messaging channel or automation rules. The lab should teach a small AI integration without exposing private calendar data or sending communications.

Google Calendar supports appointment schedules with a booking page that can be shared by link. Google documents that a candidate can book from that page and the appointment is added to the calendar; availability conflicts are managed by the booking page. The booking page is public to anyone who has the link and shows the page, account name, and profile photo. The recruiter must inspect the page before sharing it.

## Options considered

1. **Use a Google Calendar appointment schedule link configured by the recruiter.** Google handles availability and booking; the agent includes the URL in a recruiter-reviewed draft. No calendar OAuth or messaging API is needed.
2. **Use the Google Calendar API to list events, query free/busy, and create events.** This needs additional Google authorization, exposes more data, and duplicates the booking page's availability and event-creation behavior for this user journey.
3. **Send messages directly through WhatsApp/email.** This requires channel selection, candidate authorization rules, provider credentials, and recruiter-approved content, none of which are defined in the supplied discovery notes.

## Decision

Use option 1 for V1. Build a .NET 11 console app that collects a short role summary and reason for interest, sends those values to a local Ollama model to draft a professional Brazilian Portuguese invitation, appends the configured HTTPS booking URL exactly in application code, and displays the result for the recruiter to copy and send through a channel they choose.

The recruiter may include only non-sensitive professional skills and experience gathered manually from a candidate's public professional profile in the reason-for-interest context. The app does not search for, retrieve, or verify profile information, read email, access contacts, or read private calendar events. Its Calendar use is limited to the recruiter-provided booking-page URL.

The user selected this V1 on 2026-10-20. The app does not call Google Calendar APIs, read calendar event details, create booking schedules, send messages, or retain input/output. The recruiter creates and configures the booking page in Google Calendar, copies its link into local configuration, and remains responsible for choosing a channel and sending the draft.

## Consequences

- Google Calendar access is provided through the configured booking-page link; the lab does not need OAuth scopes or Google client secrets.
- The candidate's booking and confirmation are handled by Google Calendar.
- The recruiter must configure availability and check what information the public booking page displays before sharing it.
- The lab demonstrates drafting and booking-link integration, not automated recruiting operations.
- Direct messaging, calendar API operations, and multiple recruiter calendars remain deferred until the Recruiter validates the workflow and permissions.
